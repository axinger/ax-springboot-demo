# Spring Boot 3 OAuth2 企业版需求与设计文档

## 1. 项目概述

### 1.1 项目背景

基于 Spring Boot 3 和 Spring Authorization Server 的 OAuth2 企业级演示项目，支持微服务架构和单体应用两种部署模式。

本项目目的是演示学习 `spring-boot-starter-oauth2-authorization-server` 在企业场景中的使用，涵盖授权服务器、资源服务器、OAuth2 客户端的完整交互流程。

### 1.2 技术栈

| 技术 | 版本 | 说明 |
|------|------|------|
| Spring Boot | 3.5.8 | 核心框架 |
| Java | 21 | 开发语言 |
| MySQL | 8.0+ | 关系型数据库 |
| MyBatis-Plus | 3.5.15 | ORM 框架 |
| Spring Authorization Server | 最新 | OAuth2 授权服务器 |
| Spring Security OAuth2 Resource Server | 最新 | 资源服务器 |
| Spring Security OAuth2 Client | 最新 | OAuth2 客户端 |
| Thymeleaf | 最新 | 模板引擎 |

### 1.3 架构模式

```
微服务模式                          单体模式
------------                    ------------
server:9000  (授权服务器)         allinone:9003
  |                                 |
  |--- OAuth2 授权流程              |--- 授权服务器
  |                                 |--- 资源服务器
resource:9001 (资源服务器)          |--- Web UI
  |                                 |
  |--- JWT 保护 API                 
  |
client:9002  (OAuth2 客户端)
  |
  |--- Web UI + 调用资源 API
```

```

│   ├── 自定义登录页 / 授权确认页
│   └── JDBC 存储客户端/授权/授权确认

├── a21-springboot3-oauth2-resource    # 资源服务器 (端口 9001)
│   ├── 消息管理 REST API
│   ├── JWT 令牌验证
│   └── 方法级权限控制 @PreAuthorize
│
├── a21-springboot3-oauth2-client      # OAuth2 客户端 (端口 9002)
│   ├── OAuth2 登录集成

│   └── 调用资源服务器 API
│
└── a21-springboot3-oauth2-allinone    # 单体合并 (端口 9003)

    ├── 单进程运行

```

### 2.2 端口与职责

| 模块 | 端口 | 角色 | 核心职责 |
|------|------|------|----------|
| server | 9000 | 授权服务器 | 用户认证、OAuth2 授权、JWT 签发 |
| resource | 9001 | 资源服务器 | 受保护 REST API、JWT 验证 |
| client | 9002 | OAuth2 客户端 | 登录集成、Web UI、调用 API |
| allinone | 9003 | 三合一单体 | server + resource 合并运行 |

## 3. Client 角色详解

### 3.1 本项目的 client 是什么？

`a21-springboot3-oauth2-client`（端口 9002）是一个 **OAuth2 客户端 Web 应用**。它不是普通的前端页面，而是一个完整的后端服务，职责是：

1. **代表用户向授权服务器申请 Access Token** — 通过 OAuth2 授权码流程登录
2. **存储和管理用户的访问令牌** — 由 Spring Security OAuth2 Client 自动维护
3. **调用资源服务器的 API** — 使用获取到的 Access Token 访问受保护资源
4. **将资源数据渲染成页面展示给用户** — 使用 Thymeleaf 模板引擎

简单说：client 是**用户与资源之间的桥梁**。用户通过 client 的页面操作，client 背后用 OAuth2 令牌去调用资源服务器。

### 3.2 为什么需要一个独立的 client 服务？

在微服务架构中，各服务职责分离：

| 服务 | 知道用户的密码吗？ | 能访问受保护资源吗？ | 职责 |
|------|------------------|-------------------|------|
| 授权服务器 | 是（验证密码） | 否 | 只负责发令牌 |
| 资源服务器 | 否 | 是（验证令牌） | 只负责提供 API |
| client | 否（只转发） | 是（持有令牌） | 负责交互和展示 |

client 服务自己**不知道用户密码**，也不直接存储业务数据。它的作用是：
- 将用户引导到授权服务器登录
- 拿到令牌后代表用户去调用资源服务器
- 把资源服务器返回的 JSON 数据渲染成 HTML 页面

### 3.3 如果增加一个 App（移动端），和 Java client 有什么区别？

App（iOS/Android）和 Java client 都是 **OAuth2 客户端**，但形态完全不同：

| 对比维度 | Java Client（本项目） | App（移动端） |
|---------|---------------------|-------------|
| **应用类型** | 服务端 Web 应用 | 原生/混合移动应用 |
| **运行位置** | 部署在服务器（9002端口） | 安装在用户手机 |
| **OAuth2 授权模式** | 标准授权码模式 | PKCE 扩展的授权码模式 |
| **密钥安全** | 密钥存储在服务端，安全 | 无密钥（公共客户端），靠 PKCE 防攻击 |
| **会话管理** | 服务端 Session + Cookie | 手机本地 Token 存储（Keychain/Keystore） |
| **用户界面** | 浏览器渲染 Thymeleaf 页面 | App 原生 UI（SwiftUI / Jetpack Compose） |
| **回调地址** | `http://127.0.0.1:9002/...` | `com.example.app://oauth2/callback` |

**核心区别：Java client 是"服务端代理"模式，App 是"直连"模式。**

- Java client 的 OAuth2 流程发生在**服务端** — 用户的浏览器与 client 服务端交互，client 服务端再去和授权服务器交互
- App 的 OAuth2 流程发生在**用户设备上** — App 直接打开浏览器/系统授权页，获取令牌后存在手机里

### 3.4 App 调谁的接口？

**App 直接调用资源服务器的 API，不经过 Java Client。**

```
┌─────────────────────────────────────────────────────────────────────┐
│                         完整调用链路                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌──────────┐         ┌──────────────┐         ┌──────────────┐   │
│   │   App    │         │  授权服务器   │         │  资源服务器   │   │
│   │ (手机)   │         │ (server:9000)│         │(resource:9001)│  │
│   └────┬─────┘         └──────┬───────┘         └──────┬───────┘   │
│        │                      │                        │           │
│        │  1. 请求授权          │                        │           │
│        │ ───────────────────> │                        │           │
│        │                      │                        │           │
│        │  2. 返回 Access Token│                        │           │
│        │ <─────────────────── │                        │           │
│        │                      │                        │           │
│        │  3. GET /api/messages│                        │           │
│        │    Bearer {token}    │                        │           │
│        │ ────────────────────────────────────────────> │           │
│        │                      │                        │           │
│        │  4. 返回消息列表      │                        │           │
│        │ <──────────────────────────────────────────── │           │
│        │                      │                        │           │
│   └────┴──────────────────────┴────────────────────────┴───────┘   │
│                                                                     │
│   注意：App 和 Java Client 是平行关系，没有调用关系                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**关键点：**

1. **App 和 Java Client 是平级关系** — 它们都是授权服务器注册的客户端，各自独立获取令牌
2. **App 不调用 Java Client 的接口** — Java Client 没有对外暴露任何给 App 用的 API
3. **App 和 Java Client 调用同一个资源服务器** — 都是 `resource:9001` 的 `/api/messages`、`/api/user/info` 等接口
4. **令牌格式相同** — 不管是 Java Client 还是 App，拿到的 JWT Access Token 格式一样，资源服务器统一验证

### 3.5 企业场景中的多客户端架构

在实际企业中，一个授权服务器通常服务多个客户端：

```
                          ┌─────────────────┐
                          │   授权服务器     │
                          │  (server:9000)  │
                          │                 │
                          │ 注册客户端:      │
                          │ • messaging-client      (Java Web)
                          │ • mobile-app            (iOS/Android)
                          │ • mini-program          (微信小程序)
                          │ • third-party-partner   (第三方合作)
                          └────────┬────────┘
                                   │
              ┌────────────────────┼────────────────────┐
              │                    │                    │
              ▼                    ▼                    ▼
     ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
     │  Java Web Client │  │   App (手机)    │  │   小程序        │
     │  (本项目的client) │  │                 │  │                 │
     └────────┬────────┘  └────────┬────────┘  └────────┬────────┘
              │                    │                    │
              └────────────────────┼────────────────────┘
                                   ▼
                          ┌─────────────────┐
                          │   资源服务器     │
                          │ (resource:9001) │
                          │                 │
                          │ /api/messages   │
                          │ /api/user/info  │
                          └─────────────────┘
```

所有客户端的地位平等，都从授权服务器获取令牌，都直接调用资源服务器。资源服务器只认**有效的 JWT 令牌**，不关心令牌是谁发来的（Java Client 还是 App）。

## 4. 快速开始

### 4.1 环境要求

- JDK 21+
- MySQL 8.0+
- Maven 3.9+

### 4.2 数据库准备

```bash
# 创建数据库（只需执行一次）
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS ax_oauth2 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

启动 `server` 或 `allinone` 时，会自动执行 `schema.sql` 和 `data.sql` 初始化表结构和数据。

### 4.3 运行方式

**方式一：微服务模式（完整体验 OAuth2 流程）**

```bash
# 终端1：启动授权服务器
mvn spring-boot:run -pl a21-springboot3-oauth2-server

# 终端2：启动资源服务器
mvn spring-boot:run -pl a21-springboot3-oauth2-resource

# 终端3：启动客户端
mvn spring-boot:run -pl a21-springboot3-oauth2-client
```

访问客户端首页：`http://127.0.0.1:9002/`

点击"OAuth2 登录" -> 跳转授权服务器登录页 -> 输入 admin/123456 -> 授权确认 -> 返回客户端

**方式二：单体模式（快速体验）**

```bash
# 启动 All-in-One
mvn spring-boot:run -pl a21-springboot3-oauth2-allinone
```

访问：`http://127.0.0.1:9003/`

直接通过表单登录，无需跨服务 OAuth2 流程。

### 4.4 默认账号

| 用户名 | 密码 | 角色 |
|--------|------|------|
| admin | 123456 | ROLE_ADMIN, ROLE_USER |
| user | 123456 | ROLE_USER |

### 4.5 已注册 OAuth2 客户端

| 客户端ID | 密钥 | 授权模式 | Scope |
|----------|------|----------|-------|
| messaging-client | 123456 | 授权码、刷新令牌、客户端凭证 | openid, profile, message.read, message.write |
| device-message-client | 无 | 设备码、刷新令牌 | message.read, message.write |

## 6. 核心设计说明

### 6.1 用户认证

- 从内存用户升级到数据库用户存储
- `SysUser` 实现 `UserDetails` 接口
- `CustomUserDetailsService` 从数据库加载用户及角色
- 密码使用 BCrypt 加密

### 6.2 JWT 配置

- 使用 RSA 2048 位非对称加密
- 启动时动态生成密钥对
- 资源服务器通过 JWKS 端点获取公钥验证签名

### 6.3 单体模式设计

- `allinone` 模块依赖 `server` + `resource`
- `resource` 的 `ResourceServerConfig` 标注 `@Profile("!allinone")`
- `allinone` 激活 `allinone` profile，resource 的独立安全配置不加载
- 授权服务器的 `defaultSecurityFilterChain` 已包含 JWT 验证，统一处理所有请求

### 6.4 权限控制

- RBAC 模型：用户 -> 角色 -> 权限
- 方法级权限：`@PreAuthorize("hasAuthority('SCOPE_message.read')")`
- Scope 权限来自 OAuth2 授权范围
- Role 权限来自数据库角色配置

## 8. 常见问题

**Q: 如何添加新的 OAuth2 客户端？**
A: 修改 `AuthorizationConfig.java` 的 `registeredClientRepository` 方法，添加新的 `RegisteredClient` 配置。重启后自动更新数据库。

**Q: 单体模式下 OAuth2 流程是否可用？**
A: 可以。allinone:9003 同时作为授权服务器和客户端回调地址，已配置支持 `http://127.0.0.1:9003/login/oauth2/code/messaging-client-oidc`。

**Q: 数据库表如何初始化？**
A: 启动 server 或 allinone 时，`spring.sql.init` 会自动执行 `schema.sql`（建表）和 `data.sql`（初始数据）。使用 `INSERT IGNORE` 避免重复插入。

**Q: 资源服务器如何验证 JWT？**
A: 微服务模式下通过 `jwkSetUri("http://localhost:9000/oauth2/jwks")` 获取公钥。单体模式下由授权服务器的本地 `JwtDecoder` 处理。
